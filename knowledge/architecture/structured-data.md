# Structured data (Schema.org JSON-LD)

The SPA is JavaScript-rendered, so all Schema.org markup is **edge-rendered** by
`functions/_middleware.js` before the SPA boots. Each document navigation gets a
single `<script type="application/ld+json">` holding one `@graph` array whose
nodes cross-reference each other by stable `@id`.

## Source of truth
- `scripts/build-seo-data.py` → `data/seo.json` (consumed by the middleware) and
  `data/catalog.jsonld` (the public catalogue feed).
- Inputs (never duplicated): `js/data.js` (PARTIES, ELECTIONS, NATIONS,
  DEVOLVED_PORTALS), `data/manifestos-index.json`, manifesto frontmatter
  (`manifestos/<eid>/<pid>/manifesto.md` → `sections:` become `keywords`), the
  presence of `manifesto.pdf` / `manifesto.md` / `cover.jpg`, devolved election
  JSON (`data/devolved/<portal>/<year>.json` → per-page manifesto lists), and
  `data/party-links.json` (curated `sameAs`).

Always re-run `python3 scripts/build-seo-data.py` after touching any of those.

## Page metadata (titles, descriptions, OG)
- Shared helpers live in `js/meta.js` (client) and mirror the logic in
  `functions/_middleware.js` (edge). Both use the suffix
  ` — The British Manifesto Archive`.
- Per-route Open Graph images are generated by `scripts/build-og-images.py` into
  `/og/…` (party, election, manifesto, nation, devolved, and hub cards) plus
  `og-image.jpg` for the homepage. The pipeline uses
  `tools/og-generator/og.html` (HTML/CSS renderer) with specs from
  `tools/og-generator/build-manifest.mjs` (derived
  from `data/seo.json`). Requires Node.js and `npm install` (Puppeteer).
  Incremental re-renders skip unchanged cards via `og/.og-hashes.json`. The
  edge middleware points each page's `og:image` at the matching card; client
  `setPageMeta()` keeps OG/Twitter image tags on SPA navigation instead of
  stripping them after the homepage.
- Party pages include a visible answer-first `.party-lede` under the H1 and use
  `party.description` + chamber counts for meta descriptions (see `js/data.js`).
- Machine-readable site summary: `/llms.txt` (linked from `robots.txt`).

## What each route emits
- `/` and `/about`: `WebSite` + `Organization` + `DataCatalog` (`siteGraph`).
- `/manifesto/:eid/:pid`: `DigitalDocument` (stable `@id`, `encoding[]` for
  HTML/PDF/Markdown, `image`, `keywords`, `isAccessibleForFree`, `author` +
  `copyrightHolder` = party, `provider`/`publisher` = archive, `about` = the
  election `Event`, `isPartOf` = catalog) + `Organization` + `BreadcrumbList`.
- `/election/:id`: `Event` + `BreadcrumbList` + `ItemList` of that election's
  manifestos.
- `/party/:id`: `Organization` (with `description`, `sameAs`) + `BreadcrumbList`
  + `ItemList` of that party's manifestos.
- `/election/westminster`, `/party`, `/party/all`, `/election`, `/nation`, `/party/other`, `/party/european-groups`: `BreadcrumbList` + `ItemList` where listed.
- `/manifesto`: `BreadcrumbList` only (do not emit a hundreds-item `ItemList` of covers).
- `/election/:portal` and `/election/:portal/:year`: `BreadcrumbList` (+ `Event`
  and a manifesto `ItemList` on the year page).
- `/search` and `/search?q=`: `WebSite` (with `SearchAction`) + `BreadcrumbList`.
  Query string is included in `<title>` when present.
- `/nation/:id` (four nations only; `/nation/europe` 301s to `/party/european-groups`): `BreadcrumbList`.
- `/election/:portal/other-parties`: valid route with meta; OG image still at
  `/og/devolved/{portal}/other-parties.jpg`.

## Deliberate omissions
- **No `FAQPage`** — there is no visible FAQ.
- **No manifesto text in initial HTML** — manifesto bodies are fetched client-side
  from `manifesto.md` after the SPA loads. Edge metadata and JSON-LD describe
  the document; full-text prerendering is deferred until more manifestos are
  transcribed.

`SearchAction` is on the `WebSite` node (`/search?q={search_term_string}`) now
that `/search` is a crawlable SPA route (audit **2.7**).

## Catalogue feed
`data/catalog.jsonld` is a `DataCatalog` with three `Dataset`s (general
manifestos, devolved/regional manifestos, election results). Each on-disk
folder is one `DigitalDocument` at `/manifesto/{key}` — London editions that
also live in `manifestos-index.json` are not listed twice. Hero totals come
from unique keys in [`archive-counts.json`](../../data/archive-counts.json).
See [manifesto-hub](../design/manifesto-hub.md). It is linked from
every page via `<link rel="alternate" type="application/ld+json"
href="/data/catalog.jsonld?v=…">` in `index.html` (cache-busted like other
assets — see [cache-busting](./cache-busting.md)).

## Crawler / content-signal settings
Cloudflare may manage crawler and AI content-signal settings (and can serve a
managed `robots.txt`/headers) in the dashboard. Those **live settings can differ
from the committed `robots.txt`** — do not overwrite dashboard settings blindly
from the repo. Check Cloudflare → the live project before changing crawl policy.

The committed `robots.txt` points crawlers at `sitemap.xml` and `/llms.txt`.

## hreflang
Single-language site (`lang="en-GB"` on `<html>`). Each page sets
`<link rel="alternate" hreflang="en-GB">` to the canonical URL via `setPageMeta`
(client) and edge middleware (initial HTML).
