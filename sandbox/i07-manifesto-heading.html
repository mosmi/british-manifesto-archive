I07 — Manifesto dual H1 + weak document.title

Example page: /manifesto/2024/labour. The audit flagged two related problems. The proposal below is structural (heading outline + browser tab), not a visual redesign — the page should look almost the same.

What is wrong today

  • Two H1s: page chrome uses <h1 class="manifesto-viewer-title">Labour Manifesto 2024</h1>, then ~257 transcribed manifesto.md files also start with # Labour Party Manifesto 2024, which becomes a second <h1> inside the article.
  • Thin tab title: setPageMeta({ title: displayName }) → Labour — The British Manifesto Archive (no “Manifesto”, no year), while the visible chrome title already includes both.

What would change in code (if approved)

  1. Tab title only: pass the same string as the chrome H1 into setPageMeta — e.g. Labour Manifesto 2024 → Labour Manifesto 2024 — The British Manifesto Archive. No layout change.
  2. Single H1: after Markdown is parsed, demote the first content <h1> to a non-heading element (<p class="manifesto-doc-masthead">) keeping today’s body-title styling. Later h2/h3 sections stay as headings (TOC unchanged — TOC already keys off h2).
  3. Not changing: source manifesto.md files, cover treatment, body copy, or the visible chrome title wording.

Rejected alternative (for contrast)

Drop the chrome <h1> and keep the markdown title as the only H1. That would also fix the dual-H1 rule, but it makes the archive chrome title (used for breadcrumbs / prev-next orientation) no longer the document landmark — worse for skim readers who never scroll into the transcription. Prefer keeping chrome as the sole H1.
